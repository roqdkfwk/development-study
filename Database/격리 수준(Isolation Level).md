# 격리 수준(Isolation Level)

---

## 격리 수준

동시에 여러 트랜잭션이 실행될 때 **데이터 일관성을 보장하기 위해 설정**하는 데이터베이스의 동시성 제어 방법이다.

격리 수준이 높을수록 데이터 일관성은 보장되지만, 성능 저하가 발생할 수 있다.

## 트랜잭션에서 발생할 수 있는 문제

### Dirty Read

다른 트랜잭션이 **커밋되지 않은 데이터를 읽는 현상**이다.

예를 들어, 트랜잭션 A가 수정한 데이터를 트랜잭션 B가 읽었는데, 트랜잭션  A가 롤백되면 트랜잭션 B는 잘못된 데이터를 보게 된다.

---

### Non-Repeatable Read

같은 데이터를 **두 번 조회했을 때 결과가 다른 경우**이다.

예를 들어, 트랜잭션 A가 데이터를 읽은 후, 트랜잭션 B가 데이터를 수정/커밋하면 트랜잭션 A가 다시 읽을 때 값이 달라진다.

---

### Phantom Read

동일한 쿼리를 두 번 실행했을 때, **새로운 행이 나타나는 현상**이다.

예를 들어, 트랜잭션 A가 조건에 맞는 데이터를 조회했는데, 그 사이 트랜잭션 B가 새로운 데이터를 추가하면 트랜잭션 A가 다시 조회할 때 새로운 데이터가 나타난다.

---

## 격리 수준의 종류 및 설명

### READ UNCOMMITED (읽기 미확정)

트랜잭션이 커밋하지 않은 데이터를 다른 트랜잭션에서 읽을 수 있다.

**성능이 가장 빠르다.**

**데이터의 일관성이 가장 낮다.**

- **Dirty Read 허용**
- **Non-Repeatable Read 허용**
- **Phantom Read 허용**

---

### READ COMMITED (읽기 확정)

대부분의 DBMS에서의 기본값이다.

트랜잭션이 커밋된 데이터만 읽을 수 있다.

**성능과 일관성의 균형이 좋다.**

- **Dirty Read 방지**
- **Non-Repeatable Read 허용**
- **Phantom Read 허용**

---

### REPEATABLE READ (반복 읽기)

트랜잭션이 시작된 시점의 데이터를 반복해서 읽을 수 있다.

**Phantom Read**를 허용하므로 **SERIALIZABLE보다 성능이 좋다.**

- **Dirty Read 방지**
- **Non-Repeatable Read 방지**
- **Phantom Read 허용**

---

### SERIALZABLE (직렬화)

트랜잭션을 직렬화하여 실행하므로 동시 실행이 불가능하고 가장 엄격한 격리 수준이다.

성능이 가장 낮다.

데이터의 일관성이 보장된다.

- **Dirty Read 방지**
- **Non-Repeatable Read 방지**
- **Phantom Read 방지**
